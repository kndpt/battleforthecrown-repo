### Looks bad but fine (vérifié, non retenu)

- **Village-load-then-guard trio** (recruit-troops / recruit-noble / upgrade-building) : les
  `if (!village|!stock|!population) throw NotFound` semblent dupliqués, mais les loads sont
  batchés dans un unique `Promise.all` intra-`$transaction` avec des entités domaine
  spécifiques interleavées ; extraire le trio casserait le batch parallèle. Guards ≤3 lignes.
- **Ownership guards** : déjà consolidés via `OwnershipService.assertVillageOwnedBy` — pas de dup.
- **combat.worker `for…of` sur unit maps** : itérations en mémoire sur `UnitMap`, pas de N+1 DB.
- **extraction-lifecycle « god service »** (G2) : intentionnel, ADR-12 en tête de fichier.
- **`$transaction` × 54** : chacun protège un invariant serveur-authoritative distinct.
- **WL1 world-lifecycle loops** : tx-count, pas resilient batch (déjà noté).

## Phase 2 — Refactor : thème **UA1** (unit-availability guard)

Consolidation de la garde « unités disponibles » dupliquée 3× → `modules/combat/unit-availability.ts` :

- `assertUnitsAvailable(available, requested, locationLabel?)` : loop, skip `<=0`/undefined,
  throw `BadRequestException('Insufficient X<label>: have Y, need Z')` au 1er manque.
  `locationLabel = ' in garrison'` préserve le message de la variante garrison.
- `toUnitQuantityMap(rows)` : `Object.fromEntries(rows.map(r => [r.unitType, r.quantity]))`
  (dup 3× aussi).

Sites migrés :
1. `combat.service.ts` recall garnison (recallReinforcement) — message `… in garrison`.
2. `combat.service.ts` `verifyAndDeductUnits` (inventory, via initiateCaravan).
3. `initiate-extraction.use-case.ts` escort deduction (le commentaire pointait déjà
   `verifyAndDeductUnits`).

Comportement identique : `|| 0` ≡ `?? 0` pour quantités DB non-négatives ; conditions de skip
(`quantity === undefined || quantity <= 0` vs `qty ?? 0 <= 0`) équivalentes. Seule la garde
(check) est factorisée ; les boucles de décrément (clés composites Prisma divergentes) restent
sur place.

Helper Nest-scoped (`BadRequestException`) dans un fichier dédié → `combat.utils.ts` reste pur.
Diff : combat.service.ts −19 net, initiate-extraction −6 net, +42 helper, +spec.
