# Refactor Backend — 2026-07-16

## Thème retenu : W1a — extraction du scout arrival hors du god-worker `combat.worker.ts`

`combat.worker.ts` (2012 L) faisait cohabiter 4 kinds d'expédition (ATTACK combat,
SCOUT, REINFORCE, CARAVAN) + tous leurs helpers privés — le finding W1 (High) du
backlog, nominé « candidat #1 ». L'extraction complète (les 3 kinds non-combat) est
L effort sur un chemin critique couvert uniquement par smokes ; découpée en tranches
pour rester vérifiable et reviewable en un run autonome. Tranche 1 = **scout**, la plus
isolée : lecture seule vis-à-vis de l'état combat (aucun loot-to-defender, aucune
conquête), auto-contenue (fait tout inline, pas de couplage post-commit), déjà couverte
par `scouting.smoke` + `intel.smoke`.

### Changements

- **Nouveau** `combat/scout-arrival.service.ts` (`ScoutArrivalService`, 282 L) — collaborateur
  calqué sur `ExtractionLifecycleService`. `handleArrival(tx, expedition)` reçoit la
  transaction du worker (même tx Serializable) → zéro changement de comportement, d'event
  (`scout.reported`), ni d'ordre d'écriture. Le helper privé `snapshotOwnerInactivity`
  déménage avec.
- **`combat.worker.ts`** : dispatch `SCOUT` délègue à `this.scoutArrival.handleArrival(...)`.
  Suppression des méthodes `handleScoutArrival` + `snapshotOwnerInactivity` (−256 L brut).
  Constructeur : `NewbieShieldService` + `FriendshipService` retirés (déps scout-only) ;
  `ScoutArrivalService` ajouté. 7 imports shared scout-only supprimés
  (`deriveScoutPrecision`, `isIntelCompositionRevealed`, `isStrategyRevealed`,
  `representativeIntelResources`, `representativeIntelUnits`, `scoutSpyCount`,
  `computeInactivityState`).
- **`combat.module.ts`** : `ScoutArrivalService` ajouté aux providers. `WorldModule` +
  `FriendshipModule` déjà importés → déps du service résolues sans changement d'imports module.
- **Docs** : `docs/architecture/backend-modules.md` — file-tree combat (+ scout-arrival.service)
  et flow §2 (worker route par kind, scout délégué).

### Pourquoi ce découpage (et pas le split complet)

- Chemin combat = couverture smoke uniquement (policy interdit mock Prisma en unit) →
  un split de 3 kinds en un PR = surface de régression + charge de review trop large pour
  un run nocturne autonome.
- Scout établit le pattern collaborateur ; caravan + reinforce suivent (W1b) au même moule.

### Invariants préservés

- **Serializable tx** : le service opère dans la tx du worker (`tx` passé), pas de nouvelle tx.
- **Outbox** : `createOutboxEvent(tx, 'scout.reported', ...)` inchangé, même tx.
- **pg-boss** : `this.boss.send('combat:return', ...)` inchangé (même send inline qu'avant).
- **Fog / intel** : logique `deriveScoutPrecision` / `representativeIntel*` déplacée verbatim.
