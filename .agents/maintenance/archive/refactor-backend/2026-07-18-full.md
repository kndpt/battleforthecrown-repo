# refactor-backend — 2026-07-18

## Cible
Audit backend + 1 PR thème cohérent. Suite décompo god-objects combat (worker terminé W1a/W1b → cible service).

## Thème retenu : Q1 — extraction read-model `ExpeditionQueryService`

`combat.service.ts` (1634 L) était le plus gros fichier back. Mélangeait :
- **écriture** : orchestration `initiate{Attack,Scout,Reinforce,Caravan,Recall}` + `recallEnRoute` (tx Serializable + Outbox).
- **lecture** : 6 projections read-only exposées par le controller (`getActiveExpeditions`, `getIncomingAttacks`, `getOpenConquests`, `getCapturesTargetingMe`, `getOpenExpeditions`, `getGarrison`) + helper privé `toCaptureTier` + interface `GarrisonLineDto`.

Le bloc lecture (0 mutation, 0 Outbox, seule dép = `PrismaService`) forme un cluster net. Mêmes callers uniques = le controller. Pattern déjà établi dans le module (les *reports* délèguent à `CombatReportService`/`ReinforcementReportService`/`CaravanReportService`).

### Action
- Nouveau `combat/expedition-query.service.ts` (`ExpeditionQueryService`, 364 L) : 6 queries + `toCaptureTier` privé + `GarrisonLineDto` déplacée. Inject `PrismaService` seul.
- `combat.service.ts` : bloc supprimé (1634 → 1287 L, **−347**). `sumActiveOutgoingCaravanResources` **gardé** (utilisé par mutation `initiateCaravan` l.633, prend `tx`). Imports scope-only retirés : `IncomingAttackDto`, `DefenderCaptureDto`, `OpenConquestDto`, `OpenExpeditionDto` (gardé `TargetKind`), `parseUnitMap`.
- `combat.module.ts` : `ExpeditionQueryService` ajouté aux providers (non exporté — aucun consumer hors controller).
- `combat.controller.ts` : injection `expeditionQuery` ; 6 endpoints délèguent au nouveau service (`this.combatService.getX` → `this.expeditionQuery.getX`).

**Zéro changement comportement** : corps des méthodes copiés à l'identique (mêmes requêtes Prisma, mêmes DTO, mêmes gardes ownership `NotFoundException`, même tri). Aucune migration, aucune balance.
