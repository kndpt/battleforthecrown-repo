# refactor-pixi — 2026-07-10 — consolidate-duplicate-utilities

## Theme

Consolidate duplicate utility functions across the pixi frontend: `tierFromPower` (DRY-04), `DATE_FORMATTER` (NEW-01), and remaining `NumberFormat` duplicates (NEW-06/NEW-07).

## Findings fixed

### DRY-04 (Crit → FIXED+BUG)

3 independent `tierFromPower` implementations with divergent thresholds:
- `PowerBottomSheet.tsx:19` — `villageTierFromPower(power: number)` caps at tier 5
- `PlayerProfileSheet.tsx:176` — `playerProfileTierFromPower(power: string)` caps at tier 5
- `MultiVillageBottomSheet.tsx:163` — `tierFromPower(power: string)` includes tier 6 at >=5000

**Bug**: PowerBottomSheet and PlayerProfileSheet never returned tier 6, despite village assets existing for 6 tiers and `VillageVisualTier` being `1|2|3|4|5|6` (shared package). A village with power >= 5000 would show tier 5 sprite instead of tier 6.

**Fix**: Created `lib/villageTier.ts` with `villageTierFromPower(power: number)` (correct 6-tier thresholds) and `parseAndTierFromPower(formatted: string)` for design-system callers that receive pre-formatted power strings. 14 test cases.

### NEW-01 (Med → FIXED)

3 identical `new Intl.DateTimeFormat('fr-FR', {day:'2-digit', month:'2-digit', year:'numeric', hour:'2-digit', minute:'2-digit'})` in combat report views:
- `caravanReportView.ts:14`
- `combatReportView.ts:23`
- `reinforcementReportView.ts:17`

**Fix**: Added `REPORT_DATE_FMT` export to `lib/formatters.ts`. All 3 files now import the shared singleton.

### NEW-06 (Low → FIXED)

`worldsViewModel.ts:155` created `new Intl.NumberFormat("fr-FR")` instead of importing `NUMBER_FMT`.

**Fix**: Import `NUMBER_FMT` from `lib/formatters.ts`.

### NEW-07 (new → FIXED)

`TroopDetailModal.tsx:116` used `value.toLocaleString("fr-FR")` (creates transient formatter per call) instead of shared singleton.

**Fix**: Import `NUMBER_FMT`, use `NUMBER_FMT.format(value)`.
