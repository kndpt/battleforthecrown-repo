## Refactor — D05 compact number formatters

### Theme

4 compact number formatting functions with overlapping logic and divergent behavior → 1 core `formatCompact(n, opts?)` in `lib/formatters.ts` + 4 thin wrappers.

### Behavioral mapping

| Input | formatResourceAmount | formatHeaderCompact | formatCompactNumber | frShort |
|-------|---------------------|---------------------|--------------------|---------| 
| 500 | "500" | "500" | "500" | "500" |
| 1000 | "1.0K" | "1k" | "1K" | "1K" |
| 1200 | "1.2K" | "1k" | "1.2K" | "1,2K" |
| 10500 | "10.5K" | "10k" | "11K" | "10,5K" |
| 1.5M | "1.5M" | "1m" | "1500K" (BUG) | "1,5M" |

### Changes

| File | Change |
|------|--------|
| `lib/formatters.ts` | +`formatCompact(n, opts?)` core function with `decimals`, `case`, `locale` options |
| `lib/formatters.test.ts` | NEW: 13 tests covering all option combinations |

| `villageMapPanel/meta.ts` | `frShort` → 1-liner wrapper over `formatCompact(n, { locale: 'fr' })` |

### Bug fixes

1. `formatCompactNumber(1_500_000)` returned "1500K" (no M tier). Now returns "1.5M" via `formatCompact`.
2. K→M boundary: `formatCompact(999_999)` returned "1000K" because `toFixed(1)` rounds 999.999→1000.0. Added guard that promotes to M when rounded K value reaches 1000. Same fix in `formatCompactNumber` for `Math.round` path. `decimals:'none'` (floor) unaffected — `Math.floor(999_999/1000)` = 999, stays K correctly.
