# refactor-pixi 2026-07-05 — silent mutation error feedback

## Theme

7 mutation call sites fired `.mutate()` without `onError`, leaving users with zero feedback on failure (button stops spinning, nothing happens). Added toast error notifications to all of them following the existing `pushToast` + `ApiError` pattern.

## Phase 2 — Fix

### Files modified (7)

1. **BuildingCard.tsx** — `import { ApiError } from '@/api'`, `import { useUiStore } from '@/stores/ui'`, `pushToast` on `cancel.mutate` onError
2. **QueueBottomSheet.tsx** — same pattern for cancel construction
3. **VillageView.tsx** — same pattern for cancelConstruction + claimDailyCard
4. **ArmyScreen.tsx** — `pushToast` on `recallReinforcement.mutate` onError (already had pushToast imported)
5. **KingdomActivitiesBottomSheet.tsx** — `pushToast` on `recallExpedition.mutate` onError inside useMemo lambda
6. **GameHeader.tsx** — `pushToast` on `claimDailyCard.mutate` onError
7. **MapMarkerSheet.tsx** — `pushToast` on both `upsert.mutate` and `remove.mutate` onError

### Pattern used

```tsx
mutation.mutate(input, {
  onError: (err) => {
    pushToast({
      title: 'Action impossible',
      description: err instanceof ApiError ? err.message : 'Échec générique',
      tone: 'error',
      ttlMs: 4000,
    });
  },
});
```

Consistent with existing pattern in ArmyScreen (train/cancelTraining), UnitCard (disband), DefensiveFriendsSheet (friendship), BuildingDetailModal (upgrade/cancel/recruit/cancelNoble).
