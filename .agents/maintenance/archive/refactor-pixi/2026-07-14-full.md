## Findings

### TYPE-04 — SegmentedControl onChange typed as `string → void` (Med)

`SegmentedControl.onChange: (value: string) => void` forced 6 callers to cast:
- `RankingsScreen.tsx:120` → `value as Category`
- `RankingsScreen.tsx:261` → `value as GlorySub`
- `RankingsScreen.tsx:271` → `value as GloryPeriod`
- `AttackDetailModal.tsx:328` → `value as 'attack' | 'scout' | 'reinforce'`
- `MultiVillageBottomSheet.tsx:514` → `next as MultiVillageFilter`
- `PlayerProfileSheet.tsx:662` → `tab as PlayerProfileSheetTab`

**Fix**: Made `SegmentedControlOption<T>` and `SegmentedControlProps<T>` generic with `T extends string = string`. Component itself becomes `SegmentedControl<T>`. Default `= string` preserves backward compat (DesignSystemPreview callers unchanged).

5 of 6 callers lose their cast entirely. AttackDetailModal uses `as const` on inline option values (spread+ternary prevents inference).

### D07 — BuildingCard inline canAfford (Med)

`BuildingCard.tsx:81-86` reimplemented the same logic as `canAffordNextBuildingLevel` (VillageViewSectionHelpers.ts:41). Replaced with a direct call to the shared helper.

### MUT-01 — combat mutations no onError (High → RESOLVED)

State file listed `useInitiateAttack/Scout/Reinforce/Caravan/RecallExpedition/RecallReinforcement` as having "no onError (silent failure)". Audit of all 6 call sites shows **every consumer passes onError**:
- `AttackDetailModal.tsx:260` → `setError(combatErrorMessage(...))`
- `AttackDetailModal.tsx:238` → `setError(...)`
- `CaravanLaunchModal.tsx:174` → `setError(...)`
- `KingdomActivitiesBottomSheet.tsx:91` → `pushToast({tone: 'error', ...})`
- `ArmyScreen.tsx:535` → `pushToast({tone: 'error', ...})`

Pattern is call-site onError (component-level), not hook-level. All failures surface to user. False positive in state — closed.
