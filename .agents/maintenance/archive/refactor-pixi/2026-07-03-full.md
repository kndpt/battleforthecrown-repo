## Fixes applied

### F01 — army.ts: onSuccess replaces optimistic entry with server data

Added `onSuccess` callback to `useTrainUnitsMutation` that replaces the optimistic `ArmyTrainingDto` (identified by `optimistic-train-` prefix) with the actual server-returned entry containing correct `timePerUnitMs` and `nextUnitEta`. The cache is patched immediately on mutation success, before `onSettled` triggers a full refetch.

### F02 — village.ts: onSuccess replaces optimistic queue entry with server data

Added `onSuccess` callback to `useUpgradeBuildingMutation` that maps the `UpgradeBuildingResponse` to a proper `QueueEntryDto` and replaces the optimistic entry (matched by `optimisticEntryId` from context). Real `startTime`, `endTime`, and `level` from the server replace the hardcoded 60s placeholder.

### DEAD-01 — map-markers.ts: removed useUpdateMapMarkerMutation

Deleted the 45-line `useUpdateMapMarkerMutation` function and its `UpdateMapMarkerInput` interface. Removed from barrel re-export in `index.ts`. Removed unused `UpdateMapMarkerBody` import.

### CLEAN-01 — WorldMapScreen.tsx: use clear() instead of individual setters

Replaced `markersStore.setMarkers([]); markersStore.setSelectedMarkerId(null)` with `useMapMarkersStore.getState().clear()`, consistent with the `useWorldMapStore.getState().clear()` on the previous line.
