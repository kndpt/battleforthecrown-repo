# refactor-pixi — 2026-07-18 — extraction WS invalidation gaps

## Theme

Fix missing `invalidateOpenExpeditions` in all 3 extraction WS handlers and missing `invalidateRetentionSummary` in the 2 completion handlers (`extraction.returned` and `extraction.attacked` interrupted). Extraction events were the only expedition lifecycle that skipped these session-scoped invalidations, causing stale KingdomActivities UI — indefinitely stale when the extraction is the player's only active expedition (QK-01).

## Changes applied

### WS-01: extraction.started missing invalidateOpenExpeditions

`applyExtractionStarted` now calls `resolveSessionCtx()` + `invalidateOpenExpeditions(ctx, session)`. The KingdomActivities bottom sheet immediately reflects a new extraction instead of waiting up to 5s.

### WS-02 + WS-04: extraction.returned missing invalidateOpenExpeditions + retentionSummary

`applyExtractionReturned` now calls `resolveSessionCtx()` + `invalidateOpenExpeditions(ctx, session)` + `invalidateRetentionSummary(ctx, session)`. Matches the pattern of every other expedition-return handler (battle, scout, reinforcement, caravan).

### WS-03: extraction.attacked (interrupted) missing invalidateOpenExpeditions + retentionSummary

`applyExtractionAttacked` now calls `resolveSessionCtx()` at the top and, inside the `if (payload.interrupted)` branch, adds `invalidateOpenExpeditions(ctx, session)` + `invalidateRetentionSummary(ctx, session)`. When an extraction is interrupted (escort defeated), the expedition is terminated server-side — the client must remove it from the expedition list and refresh retention.

### QK-01: resolved by WS-01..03

The `openExpeditions` query uses a conditional `refetchInterval` disabled when `data.length === 0`. Before this fix, if extraction was the player's only expedition and it ended, the missing WS invalidation left the stale row cached indefinitely (no poll to rescue it). Now all 3 handlers invalidate it.

### Tests updated

3 existing test blocks in `ws-bindings.test.ts` updated to seed `setCurrentWorldSession()`, `openExpeditions`, and `retentionSummary` query data, then assert invalidation. Total assertions added: 5.
